# Short comments

Keep all output short and straight to the point — chat replies, PR bodies,
PR/issue comments, and commit messages.

- Lead with the result or the answer. No preamble, no "great question", no
  restating what the user already knows.
- Default to a few sentences and stop when the point is made.
- Use a short list or table only when it genuinely beats prose. Skip status
  recaps unless asked.
- Give long detail only when explicitly asked for a report or walkthrough.
